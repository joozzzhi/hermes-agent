# Витрина — контекстный движок

Окна нет. Контекст собирается заново на каждый запрос, как это было сделано в движке,
работавшем на сервере.

## Зачем

Встроенный движок копит разговор в окне, а когда оно заполняется — пересказывает старую часть
и продолжает с пересказа. Дальше модель опирается не на то, что было сказано, а на пересказ, и
достраивает утраченные детали. Для продукта, где важна точность, это прямой источник
выдуманных подробностей.

Здесь вместо этого: контекст — витрина, а не хранилище. Всё, что не поместилось, лежит в общей
памяти целиком и находится поиском.

## Из чего собирается запрос

| Слой | Что в нём | Как часто меняется |
|---|---|---|
| Системная часть хозяина | личность Гермеса, его инструкции | редко |
| Знание | то, что верно всегда: кто оператор, что решено, правила | редко |
| Найденное под вопрос | записи по смыслу этого вопроса | каждый запрос |
| Давний разговор | куски прошлых бесед, всплывшие по смыслу — дословно, с датой | каждый запрос |
| Свежий хвост | последние реплики, настоящими сообщениями | каждый запрос |

Устойчивое стоит первым — на нём держится кеш поставщика. Изменчивое едет вместе с самим
вопросом: системное сообщение в середине разговора принимают не все модели.

## Чего движок не делает

Не зовёт модель, чтобы что-то пересказать. Когда контекст не помещается, старое просто
отпускается — оно уже в общей памяти и находится поиском.

## Включение

```
context:
  engine: aida
```

Нужна настроенная общая память (`SUPABASE_DB_URL`) и включённый плагин памяти `aida`: движок
читает ту же базу и не заводит второго подключения. Память не настроена — движок молча не
вмешивается, и разговор идёт как с обычным движком.

## Опасное место

Хвост разговора нельзя резать между обращением к инструменту и его результатом: поставщик
отвергнет такой запрос целиком, и разговор встанет. Резка идёт только по границе, где начинается
реплика человека. Это первое, что проверяется тестами.
